# CLAUDE.md — AI Agent Guide for the `disperse` Project

## What This Project Does

Automates the full pipeline for identifying and analyzing the cosmic web (walls, filaments, clusters) in cosmological simulations using [DisPerSE](http://www2.iap.fr/users/sousbie/web/html/indexd41d.html). The pipeline takes N-body snapshot files (HDF5), runs topology extraction, and produces per-point category statistics, histograms, and visualizations.

---

## Pipeline Overview

```
HDF5 Snapshot
  └─ analyze_snapshot.py          → NDnet, NDskl, manifold/skeleton VTU/VTP files
      ├─ ndtopo_stats.py          → topology_stats.csv, topology_points.csv (per crop)
      └─ batch_clip.py            → slab VTUs, 2D VTIs, PNG renders (via pvpython)
              └─ stitch_slab_pngs.py → MP4 movies

batch_crop_and_clip.py            → orchestrates the above across a tiled grid of crops
                                     (per crop: analyze → ndtopo_stats → batch_clip per slab)

aggregate_topology_points.py      → combined statistics across all crops
```

`ndtopo_stats.py` and `batch_clip.py` are independent parallel steps after `analyze_snapshot.py` — neither depends on the other.

## Script Roles

| Script | Purpose | Runs via |
|---|---|---|
| `analyze_snapshot.py` | HDF5 → DisPerSE topology (Delaunay, manifolds, filaments) | python |
| `ndtopo_stats.py` | VTK/NDnet → per-point category membership + scalars CSV | python |
| `batch_clip.py` | Clip 3D topology to 2D slabs, render PNGs | **pvpython** |
| `batch_crop_and_clip.py` | Orchestrate above three across a volume grid | python |
| `aggregate_topology_points.py` | Aggregate per-point CSVs across crops into stats + histograms | python |
| `compare_simulations.py` | Side-by-side box plots, violin plots, and scatter+marginal-density plots comparing two simulations | python |
| `spin_render.py` | Rotating 3D renders → PNG sequence or MP4 | **pvpython** |
| `redshift_evolution.py` | Smooth redshift-evolution movie across multiple VTU snapshots | **pvpython** |
| `stitch_slab_pngs.py` | Assemble slab PNGs → MP4 via ffmpeg | python |
| `compute_density_field.py` | Particles → CIC density field HDF5 | python |
| `export_snapshot_vtu.py` | Particles → VTU point cloud | python |
| `export_grid_vti.py` | HDF5 3D array → VTI structured grid | python |

> **`batch_clip.py`, `spin_render.py`, and `redshift_evolution.py` must be run via `pvpython`** (ParaView's Python interpreter), not standard Python. They use `from paraview.simple import *`.

## Key Data Formats

### Input: HDF5 Snapshot (Quijote/Gadget)
```
/PartType1/Coordinates  → (N, 3) float32  [kpc/h]
/PartType1/Masses       → scalar or per-particle
/Header/BoxSize, MassTable
```
Quijote snapshots are Blosc-compressed — require `hdf5plugin` at import time.

### Intermediate: DisPerSE Native Formats
Filenames encode all metadata via regex-parseable tags:
- `snap_010_s3.5_manifolds_JE1a_S020.vtu`
  - `s3.5` = persistence threshold 3.5σ
  - `JE1a` = topology type (void walls)
  - `S020` = 20 smoothing passes
- Topology tags: `JE0a` (voids), `JE1a` (void walls), `JD1d` (walls), `JE2a` (clusters), `U` (filament arcs), `CUD` (cluster critical points)

### Key CSV: `topology_points.csv`
One row per Delaunay point, generated by `ndtopo_stats.py --per-point-csv`:
```
delaunay_id, is_wall, is_filament, is_filament_manifold, is_cluster, field_value, log_field_value, mass
```
Boolean columns are 0/1. This is the input to `aggregate_topology_points.py`.

### Key CSV: `topology_stats.csv`
One row per category, columns: `category, count, <scalar>_sum, <scalar>_mean, <scalar>_min, <scalar>_q25, <scalar>_median, <scalar>_q75, <scalar>_max, <scalar>_std` (repeated for each scalar).

### Histogram CSVs
`<prefix>_<category>_<scalar>_hist.csv` — one per category per scalar:
```
bin_left, bin_right, bin_center, count
```

## Category System (sigma-algebra over {W, F, C})

Three generators: **W**alls (`is_wall`), **F**ilament manifolds (`is_filament_manifold`), **C**lusters (`is_cluster`).

> Note: `is_filament` (arc-based filaments) is present in input CSVs but **intentionally excluded** from all category logic. All category names use `filmans` (not `filaments`) internally — `filmans` = filament manifolds.

The `_categories()` function (pure Python) and `polars_category_frame()` (Polars) must always agree. `ALL_CATEGORIES` must list every string either function can emit. If you add a category, update all three.

**Primary plotting categories** (used in bar charts, `COMPOSITION_COMPONENTS`):
```python
("clusters",           "Clusters",  "#f2e661")
("filmans_not_clusters","Filaments", "#fca50a")
("walls_only",         "Walls",     "#c73e4c")
("unassigned",         "Unassigned","#5d126e")
```
These four are mutually exclusive and exhaustive — every point falls into exactly one.

## `aggregate_topology_points.py` — Critical Details

This is the most complex script (~2400 lines). Three processing engines:
- `run_polars` — fast, single-pass Polars scan
- `run_polars_chunked` — Polars in N chunks (lower memory)
- `run_stream` / `main()` — pure Python (exact quantiles, slowest)

All three engines must produce identical output for the same input. When modifying statistics logic, check all three.

**Adding a new category:** Update in this order:
1. `_categories()` — pure Python row-level logic
2. `polars_category_frame()` — Polars expression mirror
3. `ALL_CATEGORIES` — the master list used for seeding output rows

**`_component_lists()` and `_component_color_map()`** both delegate to `COMPOSITION_COMPONENTS`. There is no separate `FILMAN_WALLS_COMPONENTS` — it was removed; only `COMPOSITION_COMPONENTS` is used.

**Percentage display:** Bar charts use `f"{p:.2f}%"`. The last percentage is always computed as `100.0 - sum(percents[:-1])` to prevent floating-point accumulation.

## `compare_simulations.py` — Key Details

Produces four plot types per run:

1. **Box plots** (`*_<scalar>_box.png`) — from aggregated `topology_stats.csv`; sim A uses hatched fill, sim B uses solid fill.
2. **Violin plots** (`*_<scalar>_violin.png`) — from per-point `topology_points.csv` files; requires `scipy` for KDE. `log10_field_value` is not stored in per-crop CSVs — it is computed on the fly via `math.log10(field_value)`.
3. **Scatter + marginal density, proximity** (`*_scatter_proximity.png`) — x = `field_value^(-1/3)`, y = `log10(field_value)`.
4. **Scatter + marginal density, Voronoi** (`*_scatter_voronoi.png`) — x = `field_value^(-1)`, y = `log10(field_value)`.

**Violin ordering convention:** sim B (second `--sim` argument, the earlier epoch) is drawn on the **left**; sim A is on the right. Pass `--labels` in chronological order (e.g. `"z=3" "z=0"`) and sim B will be z=3 on the left. The table columns follow the same left-to-right order.

**Equal-area KDE normalization:** All violins share a single global scale factor = `violin_w/2 / global_max_kde`, so visual area is proportional to distribution density rather than scaled per-violin to a common maximum width.

**Auto-discovery:** `--sim FOLDER` searches `FOLDER/` and `FOLDER/combined/` for `*_topology_stats.csv`; it searches all subdirectories of `FOLDER/` (excluding `combined/`) for `*_topology_points.csv`. Use `--points-file` to supply CSVs explicitly.

## Coordinate System Conventions

- Snapshots arrive in **kpc/h** by default; all scripts accept `--input-unit` / `--output-unit`
- `analyze_snapshot.py` with periodic boundaries **rebases** particle coordinates to crop origin before running Delaunay, then **shifts VTK outputs back** to global coordinates
- Slab origins in `batch_clip.py` must be in **output units**, not input units

## Refactoring Notes

- The codebase **works but has never been cleaned** — expect some dead code, duplicated logic, and inconsistent naming across scripts (especially `ndtopo_stats.py` vs `aggregate_topology_points.py` category naming)
- `aggregate_topology_points.py` has been significantly refactored: shared helpers extracted, schema detection consolidated, category system updated to sigma-algebra
- Backup scripts (`aggregate_topology_points_old.py`, `aggregate_topology_points_031726.py`, `spin_render_layers.py`) in `/scripts/` are untracked — treat as reference only
- Docs in `/documents/` describe intended behavior but may lag behind script changes — the scripts are the source of truth
- Do not assume docs and scripts are consistent with each other

### Documentation authoring conventions (Quarto/Pandoc)
- Each user guide should have: `## What it does`, `## Requirements`, `## CLI`, `## Examples`, `## Notes` (in that order where applicable).
- `compare_simulations.py` is documented inside `AGGREGATE_TOPOLOGY_POINTS_USER_GUIDE.qmd`, not a separate file.
- **Blank lines around lists are required by Pandoc:**
  - A blank line must precede a list when it follows paragraph text **or a closing code fence** (otherwise the list is not recognized).
  - A blank line must follow a list when paragraph text comes next (otherwise the paragraph is absorbed into the last list item).
  - This applies to all list styles: `- item`, `* item`, `1. item`, and `1) item`.
  - Headers and code fences after a list do not require a blank line, but it doesn't hurt.
