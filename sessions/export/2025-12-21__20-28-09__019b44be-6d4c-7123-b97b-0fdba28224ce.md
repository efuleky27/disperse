Common Markdown patterns for a figure + caption:

1) Plain Markdown (works in many renderers, including GitHub):
```
![Your caption here](path/to/image.png)
```
The alt text doubles as the caption.

2) If you need a visible caption below the image, use HTML (widely supported in MD):
```html
<figure>
  <img src="path/to/image.png" alt="Description">
  <figcaption>Your caption here</figcaption>
</figure>
```

3) With reference-style images:
```
![Caption][fig1]

[fig1]: path/to/image.png
```

Use whichever your target renderer supports best; HTML is the most explicit for a true caption element.

Here’s how those utilities fit in, and what they do that the `analyze_snapshot` scripts don’t:

- `scripts/compute_density_field.py`: builds a CIC density grid (N³ array) directly from a snapshot and writes HDF5. No DisPerSE/topology; just a regular volumetric density field with optional overdensity. Inputs: snapshot; Outputs: HDF5 with `DensityField/density` (and metadata). Use it when you want a gridded density volume rather than a topological skeleton.

- `scripts/export_grid_vti.py`: converts any 3-D dataset in an HDF5 file to a VTI (VTK ImageData) for ParaView. It reads a dataset path, writes ASCII VTI. Typically you’d run this on the HDF5 produced by `compute_density_field.py` to visualize the volume. No decimation/topology; it just rewraps an existing grid.

- `scripts/export_snapshot_vtu.py`: streams snapshot particles into a VTU (polyvertex) with optional attributes and decimation; also has a `--density-field` mode to emit VTI from a density-grid HDF5. It’s for quick particle clouds or grid export, not for DisPerSE manifolds/filaments.

What `analyze_snapshot.py` / `analyze_snapshot_2d.py` do instead: they decimate/crop, run DisPerSE (Delaunay + MSE) to produce manifolds and skeletons, and convert those NDnet/NDskl outputs to VTK formats. They don’t produce full density grids or raw particle VTUs.

Typical combos:
- Want a density volume: `compute_density_field.py` → `export_grid_vti.py` (or `export_snapshot_vtu.py --density-field …`).
- Want a raw particle VTU: `export_snapshot_vtu.py`.
- Want walls/filaments: `analyze_snapshot*.py`.

I’ll walk through the pipeline steps and why DisPerSE’s approach is essential compared to manual thresholding or just loading snapshots in ParaView.

• DisPerSE is doing the heavy lifting here:

  - It takes the raw particle catalog and rebuilds the full Delaunay tessellation so it can estimate a continuous density field (via DTFE) without going onto a fixed grid.
  - From that tessellation it computes the Morse–Smale complex, applies persistence filtering (your --nsig 3.5), and extracts only the topologically significant descending manifolds of index‑1 saddles—i.e., coherent wall surfaces—respecting periodic boundaries.
  - netconv then converts those manifolds into an actual mesh file you can visualize anywhere.

  Key DisPerSE Inputs That Shape Wall Geometry

Particle sampling (--stride/--target-count) – lowering the stride gives DisPerSE a denser point set, which captures more small-scale walls; raising it smooths over fine structure. This is the first lever on the geometry because everything downstream works on the decimated catalog.

Smoothing scale (delaunay_3D options) – DisPerSE’s triangulation doesn’t have many tunables beyond periodic boundaries and block size, but enabling --periodic (which adds the -periodic flag) makes features wrap through the domain instead of breaking at edges, crucial for large cosmological boxes.

Persistence filtering (mse -nsig/-cut) – the main control described in the linked docs: higher --mse-nsig (or higher --persistence-cut values) prunes low-significance pairs, leaving only strong walls; lower thresholds keep more tenuous structures. ### 62. assistant — 2025-12-26 02:12:35Z

Two ways to tag points, with different meanings:

1) **Distance-based labeling (proximity to extracted features)**
- What you get: a heuristic class per particle like “filament” if it’s within X of a skeleton line, “wall” if within Y of a wall surface, else “other/void.”
- How: use the exported filaments (VTP) and walls (VTU) and compute nearest-distance to each, then assign labels based on thresholds.
- Pros: simple, uses existing outputs; you control how “thick” a wall/filament is by setting the distance cut.
- Cons: it’s not a topological assignment; changing the thresholds can flip labels.

2) **Basin assignment (Morse–Smale cell ownership)**
- What you get: a topologically exact region ID for each sample point (which minimum/saddle basin it belongs to). You can derive a class (“void basin”, “wall basin”, etc.) from the owning critical point/manifold.
- How: requires working with the Delaunay/NDnet and the Morse–Smale complex to propagate ownership to vertices (or particles). DisPerSE doesn’t emit this directly; you’d need a custom pass or additional DisPerSE outputs (e.g., segs/crits) to build the mapping.
- Pros: topology-faithful and threshold-stable (given fixed `--nsig`/`--cut`).
- Cons: more complex to implement; not available out of the box in the current scripts.

In short: proximity labeling is easy and tunable but approximate; basin assignment is exact to the Morse–Smale topology but needs extra computation/data extraction.

### 69. assistant — 2025-12-26 02:20:04Z

To do it “for real,” you need the actual Morse–Smale cell each vertex/particle belongs to, not just nearest-distance. That means following the gradient on the Delaunay/NDnet until you reach a minimum and using that minimum’s ID as the basin label.

Two ways to get there:

1) If DisPerSE can emit segmentation for you (best case)
- Check DisPerSE’s options for segmentations/labels (e.g., `-segs`, `-to segs_ascii`, or similar; the exact flag depends on your DisPerSE build). If available:
  - Run `mse` with the segmentation output enabled.
  - You’ll get a file that maps each vertex in the NDnet to its owning critical point (minimum).
  - Join that mapping to your decimated particles (NDfield/VTU) and write a labeled VTU/HDF5.

2) If you have to compute it yourself (custom pass)
- Inputs needed: the NDnet from `mse` (or the Delaunay NDnet), the scalar field (DTFE density) on vertices, and the critical points list (crits).
- Algorithm outline:
  - Build the adjacency of the NDnet vertices (from the tetrahedra).
  - For each vertex, follow steepest descent (or ascend, depending on definition) through neighbors using the scalar values until you reach a local minimum (a critical point). Cache the destination to avoid recomputation.
  - Assign the destination minimum ID as the basin label for that vertex.
  - Map these labels back to your particle VTU (same vertex order as NDfield/Delaunay if you used the same decimation).
  - Write out a VTU/HDF5 with a `basin_id` array.
- This requires writing a new script to parse NDnet cells, extract the vertex positions/values, and perform the gradient flow. It’s more work but gives exact Morse–Smale ownership.
